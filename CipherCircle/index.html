Core Modules A — F

將社群互動、加密通訊與課程協作放進同一空間

以下為密圈規劃之六大功能模組（目前處於早期預售與需求登記階段，各模組上線狀態與定量門檻以正式版規格為準）。

模組 A｜視覺化內容與社群層

動態牆、短影音與私密互動

  • 支援多圖文動態牆、短影音與限時動態排版。
  • 具備點讚、表情回應、轉發、私密收藏與主題標籤整理。
  • 採 Mobile First 與響應式跨裝置介面設計。
模組 B｜端對端安全通訊

加密群聊、語音視訊與閱後即焚

  • 通訊以端對端加密為預設方向，重視前向與後向保密。
  • 支援加密群組聊天、語音／視訊通話與螢幕共享。
  • 提供限時閱後即焚訊息與本機受控金鑰備份。
模組 C｜論壇、演講與課程

加密直播授課與作業繳交

  • 階層式主題論壇、精華置頂與權限分級版塊。
  • 支援端對端加密直播授課與預約制線上演講。
  • 內建講義發布、作業加密繳交、測驗與學習進度追蹤。
模組 D｜匿名認證與資格證明

不出示真實帳號也能證明資格

  • 一般公開場合不暴露真實身分，以金鑰對建立公眾身分。
  • 透過零知識證明出示組織成員資格或閱讀權限，不必公開真實帳號。
模組 E｜密文運算

密文推薦與匿名投票

  • 於密文狀態下比對興趣標籤與內容特徵，讓服務端不必先解開原始內容。
  • 社群投票以同態加法累計票數，避免計票方在開票前看到個別選擇。
模組 F｜證據鏈與可驗證審計

簽章收據與條件式調閱

  • 重要發表、點擊、閱讀與資料調用產生簽章收據。
  • 收據打包寫入證據鏈，防止任意竄改。
  • 僅在司法仲裁或授權門檻金鑰湊齊時依規檢驗。
Data Flow & Honest Boundaries

「公開偽匿名＋條件式舉證」運作流程與誠實邊界

前端維持互動體驗，不直接執行重度密文運算；重度分析採批次處理，儲存層採信封加密且密鑰由客戶端持有。

  1. 客戶端加密與簽署
    於客戶端加密內容、簽署操作收據，並上傳加密特徵向量。
  2. 本地解密與閱讀回執
    授權成員取得內容後於本地解密閱覽，並回傳閱讀收據。
  3. 寫入證據鏈
    收據定期打包寫入證據鏈，保留可驗證紀錄。
  4. 授權門檻下查驗
    僅當符合司法仲裁或授權門檻憑證時，方可驗證特定紀錄。

密圈定位為「公開偽匿名＋條件式舉證」，不是「誰都查不到」的絕對匿名承諾。本頁亦不宣稱已通過特定司法或法規認證，或已達到外部通訊與社群平台之同等安全等級與完成度。

Frequently Asked Questions

常見問答（FAQ）

Q1：密圈是匿名到誰都查不到的平台嗎？

不是。密圈的設計是「公開環境下的偽匿名」：一般公開場合不暴露真實身分；但若授權或司法仲裁門檻滿足，特定發表或閱讀紀錄可以被驗證，讓行為在授權條件成立時無法被任意否認。

Q2：誰來保管可以調閱證據的金鑰？

系統設計為僅在「司法仲裁或授權門檻金鑰湊齊時」可以檢視特定紀錄；門檻金鑰持有者配置與規則將依部署方案定案，不於預售階段擅自補述。

Q3：平台看得到我的內容、推薦與投票選擇嗎？

通訊以端對端加密為預設方向，內容於客戶端加密後上傳；推薦匹配與匿名投票以密文運算為設計目標，避免計票方或平台在未解密原始資料前看到個別選擇。

Q4：目前的方案價格與上線時間為何？
